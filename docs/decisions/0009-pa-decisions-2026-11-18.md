### Item 6: what GitHub-hosted runners cost

Checked on 18/11/2026 in GitHub's public documentation ("GitHub Actions billing", "GitHub-hosted runners
reference", "Actions runner pricing", "Larger runners") and the GitHub changelog:

- **Standard GitHub-hosted runners, Linux and macOS, are free and unlimited in public repositories.** The
  repository is public, so the jobs of `ci.yml`, `nightly.yml` and `release.yml` would cost nothing on standard
  runners. Self-hosted runners are free too.
- **Larger runners are billed per minute, also in public repositories** (for example the `-xlarge` macOS labels).
  None of the workflows uses one.
- **The label `xcode-27`** in `ci.yml`, `nightly.yml` and `release.yml` is neither a self-hosted label nor a larger
  runner: it is GitHub's own image for Xcode 27 on Apple silicon (3 CPU, 7 GB), which the runner reference lists
  among the standard runners for public repositories, next to `macos-15`, `macos-26` and `macos-latest`. GitHub
  introduced it as a public preview in July 2026 and announced it as generally available on 15/10/2026; the
  `actions/runner-images` README still called it a preview when it was checked. [ADR 0500](0500-ci-runners-and-toolchain-pins.md)
  recorded it as the preview on 13/11/2026 and chose it because it is the only hosted image with macOS 27 and
  Xcode 27.2. Its large variant, `xcode-27-xlarge`, is a larger runner and would be billed.
- The integration suite needs granted permissions and stays on the self-hosted runner (item 7) whatever the hosted
  runners cost (QA-R12, QA-R13).

So re-enabling `CI`, `Nightly` and `Release` on the public repository would not be billed as long as they keep
standard labels. The decision stays the product owner's.
