# Architecture documents

Index of the platform-layer design: the macOS app, `Packages/AppCore`, the test host and the release
pipeline around them. The normative source is always `spec/`; these documents explain how the code meets it
and cite the requirement IDs (PLT-R, PRD-R, QA-R, CLR-R, ENG-R). The engine is specified in
[spec/01-engine.md](../../spec/01-engine.md) and lives in `Packages/VietnameseEngine/`.

Read them in this order:

| Document | What it answers |
|---|---|
| [ARCHITECTURE.md](../../ARCHITECTURE.md) | The map: system shape, module map, process and thread model, the life of one key press, host state machine, snapshot publication, per-app behaviour as data, layouts, secure input, injection, settings, diagnostics and privacy, permissions, updates, shell, testing, and "where to change what" (QA-R66). Start here. |
| [contracts.md](contracts.md) | Public Swift types, protocols and signatures of every platform module, their isolation, and the files each workstream owns. Signatures are contracts; the code blocks are spliced from the compiled sources. |
| [traceability.md](traceability.md) | One row per PLT-R, PRD-R, QA-R and CLR-R requirement: owning module or file, how it is verified, which workstream implements it, and which rows Pa verifies by hand. |
| [workstreams.md](workstreams.md) | How the platform layer is built by parallel workstreams: waves, owned paths, frozen files, rules for every workstream, acceptance criteria, and the interim verification plan before the self-hosted runner exists. |

## Tool

[`tools/sync_contracts.py`](tools/sync_contracts.py) copies the compile-checked Swift sources named by
`<!-- include: path -->` markers into `contracts.md`, so the document cannot drift from the code.

```sh
python3 -I docs/architecture/tools/sync_contracts.py           # rewrite contracts.md after a signature change
python3 -I docs/architecture/tools/sync_contracts.py --check   # exit 1 when contracts.md is stale
```

The `--check` form runs in CI (`ci.yml`, job "Architecture contracts in sync"). Only the integrator rewrites
`contracts.md`; a workstream that changes a public signature lists the change in its report
([workstreams.md](workstreams.md), "Rules for every workstream", rule 3).
