## Found while applying the decisions

- Code-only words that are not English words never reach rule L9. Spec 8.1 checks L7 ("R is not English",
  where English means the English lexicon or the tech-always list) before L9 (code context), so in a terminal
  with Vietnamese on, Telex `chown` commits `chơn` and `ef` commits `è`; `awk` keeps `ăk` by L6. ENG-R850 says L9
  restores code-only words in the code context, which holds only for code-only words that are also English
  (`tar`, `less`). The ENG-T11 notes of `awk`, `chown` and `ef` used to claim the opposite and now describe the
  real behaviour; `ProductOwnerDecisionTests` pins it. Open point for Pa: keep it, or let L9 apply to every
  code-only word in the code context (a spec change of 8.1).
